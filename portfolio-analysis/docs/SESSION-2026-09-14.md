## What this project is

Retrospective attribution of large single-day equity moves to dated, cited events.
Five CLI stages, each writing a durable artifact so any stage can be re-run alone:

```
ingest-prices → detect-moves → collect-events → explain → render
    Plan 1         Plan 1         Plan 2        Plan 3    Plan 4
     DONE           DONE          written      unwritten  spiked
```

**It explains the past and makes no predictive claim.**
Its sibling `../stock-trading-bot` is the deliberate mirror image: that repo must never see the future, this one exists to use hindsight.

## Decisions, and why

| Decision | Rationale |
|---|---|
| Standalone project, not a module of `stock-trading-bot` | Retrospective code sharing a process with point-in-time code is how a future-leak gets written |
| No Robinhood integration | Hand-written `config/portfolio.yaml`. The portfolio pull is the least interesting and most fragile part |
| v1 is META only | One name end to end beats five half-done |
| Vol-normalised abnormal return, `\|z\| ≥ 2.5` | A 3% day is noise for NVDA and a five-alarm event for ServiceNow. A fixed threshold over-samples volatile names |
| Six years of prices fetched | A 250-day beta window eats the first year; five fetched years would leave four evaluable |
| Log-scale, dual-indexed chart | META spans index 34→280; linear compresses the 2022 drawdown into illegibility. Indexing to 100 avoids a dual axis |
| Muse Spark 1.3 for attribution | Asked for by name. Strict JSON Schema + 1M context. **No Claude/Anthropic call anywhere in the pipeline** |
| Macro calendar as checked-in YAML, not FRED | FOMC/CPI/PCE dates are published years ahead and never revised. Removes a key, a network dep, and a rate limit |
| **yfinance rejected** | 115 MB of transitive deps (pandas 48M, numpy 24M, lxml 19M) around a 1.3 MB library. AV `EARNINGS` returns strictly more |
| Reddit cut from v1 | The sibling repo already built and abandoned a Reddit collector; historical recall needs a bulk archive |

### The one that matters most: the verified / reported split (spec §8)

An LLM handed "META fell 10.6%, here are 7 articles" will always produce a fluent, confident reason — including on days when nothing happened.
The structural defense is that **facts and narrative never share a checkbox**:

- **Verified** — computed in Python from a dated source. The model cannot construct one; `Document` and `VerifiedFact` are different types and it is only ever handed `Document`s.
- **Reported** — a claim asserted in sources, carried with citations and a support count.

The sharpest evidence for this split turned up while probing Alpha Vantage:

| Date | EPS surprise | Next session |
|---|---|---|
| 2024-04-24 | **beat +9.03%** | **−10.6%** |
| 2022-02-02 | **miss −4.18%** | **−26.4%** |

A beat and a miss, both followed by large declines.
A fact can be perfectly verifiable and carry zero explanatory weight.
Anything reading "beat" as bullish gets the anchor date exactly backwards.

Spec §10 adds two controls that must ship with the attribution: a **placebo** (quiet days through the identical prompt — does it abstain?) and a **sign-flip** (real evidence, inverted sign — does it still explain confidently?).

### Two claims that were wrong until measured

1. **"AV news starts ~2022, years 4-5 thin to empty."** Written into the spec from documentation. The earliest META article is `20200121T221400` — **January 2020**, before the evaluated window begins. All 30 moves are covered. The real limit is **volume: 7 documents around the 2024 anchor, 14 around the 2022 crash**, against the 37 the original mockup assumed.
2. **EDGAR `filings.recent` holds only the last 1000 filings** — for META it begins 2024-06-11. An adapter reading only it reports "no filing" for two thirds of the window, *silently, as an absence*. The archives under `filings.files[]` must be merged. Plan 2 Task 4 has a test that fails if they are not.

Operational facts, learned by probing: AV returns intermittent `502`s (twelve across three requests — retry is mandatory); a 111 KB response truncates under `urllib` with `IncompleteRead`, which `requests` handles; `ticker_sentiment` is a list over every ticker mentioned, so relevance must be read for the *requested* ticker (an Alphabet story scored 0.709 *for META*).

## Quality process, and what it caught

Plan 1 was executed with fresh subagents per batch plus two-stage review. That surfaced defects a self-review missed twice:

- **`MoveParams(z_threshold=nan)` constructed cleanly** and then suppressed every move, because `abs(z) >= nan` is `False`. Zero large moves, indistinguishable from a quiet market. `abs(-16.30) >= nan → False` — the biggest move in the dataset, silently swallowed.
- **A test fixture whose "idiosyncratic noise" was collinear with the benchmark**, leaving σ at 1e-17 and z at 1e16 while every assertion still passed. Found once, fixed in one file, and **still live in a second file** until the independent review caught the duplicate.
- **`aligned_returns` raised on short series** while its own docstring promised that was a coverage fact.
- **`zip(a, a[1:], strict=True)`** — cannot run; the arms are deliberately unequal.
- A **live partial bar** ingested as a completed day, so running `ingest-prices` mid-session could publish a spurious move.
- Two network tests that **expire deterministically** as the six-year window slides (2022-02-03 drops out ≈ Feb 2027); they now skip with the reason.

Running total: **eight plan defects during Plan 1 execution, plus sixteen review findings.**
The lesson worth carrying: *the plan's own self-review caught the fewest*. Running commands and independent review caught the rest.
